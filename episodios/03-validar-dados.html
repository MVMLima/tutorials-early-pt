Validar dados de casos

NotaPerguntas
  • Como dados brutos de casos podem ser convertidos em um objeto linelist (lista de casos)?
DicaObjetivos
  • Demonstrar como converter dados de casos em dados linelist
  • Demonstrar como marcar e validar dados para tornar a análise mais confiável
ImportantePré-requisitos

Este episódio requer que você:

  • Baixe o arquivo cleaned_data.csv
  • Salve-o na pasta data/

Introdução

Na análise de surtos, após concluir as etapas iniciais de leitura e limpeza dos dados de casos, é essencial estabelecer uma camada fundamental adicional para garantir a integridade e a confiabilidade das análises seguintes. Sem essa etapa, você pode encontrar problemas mais tarde — por exemplo, variáveis podem ser modificadas ou removidas sem intenção, ou seus tipos de dados (como <Date> ou <character>) podem mudar durante o processamento. Essa camada adicional normalmente envolve duas etapas principais:

  1. marcação (tagging): verificar se as colunas obrigatórias estão presentes no conjunto de dados e confirmar se elas têm os tipos de dados corretos.
  2. validação: implementar salvaguardas para garantir que as colunas marcadas não sejam excluídas ou alteradas acidentalmente durante as etapas posteriores de manipulação de dados.

Este episódio foca na criação de objetos linelist usando o pacote linelist, que oferece suporte nativo à marcação e à validação de dados de surtos para garantir a integridade dos dados ao longo de todo o fluxo de trabalho de análise. Vamos começar carregando o pacote {rio} para ler os dados e o pacote {linelist} para criar um objeto linelist. Usaremos o operador pipe (%>%) para conectar algumas de suas funções, incluindo outras do pacote {dplyr}. Por esse motivo, também carregaremos o pacote {tidyverse}.

# Carregar pacotes
library(tidyverse) # para funções do {dplyr} e o operador pipe %>%
library(rio) # para importar dados
library(here) # para referenciar arquivos com facilidade
library(linelist) # para marcar e validar
NotaChecklist

O operador de dois pontos duplos (::)

O :: no R permite acessar funções ou objetos de um pacote específico sem carregar o pacote inteiro no caminho de busca. Ele oferece várias vantagens importantes, incluindo:

  • Informar explicitamente de qual pacote uma função provém, reduzindo a ambiguidade e possíveis conflitos quando vários pacotes têm funções com o mesmo nome
  • Permitir chamar uma função de um pacote sem carregar o pacote inteiro com library()

Por exemplo, o comando dplyr::filter(data, condition) significa que estamos chamando a função filter() do pacote {dplyr}.

Criar um linelist e marcar colunas

Antes de começar, vale a pena distinguir as duas etapas: a marcação (tagging) atribui um papel semântico (como ID do caso ou data de início dos sintomas) a uma coluna no seu conjunto de dados, enquanto a validação verifica se as colunas marcadas ainda existem e têm os tipos de dados esperados. A marcação é feita uma única vez, quando você cria o objeto linelist; a validação é algo que você pode executar repetidamente à medida que os dados subjacentes evoluem.

Após os dados serem carregados e limpos, podemos converter os dados de casos limpos em um objeto linelist usando o pacote {linelist}, como no bloco de código abaixo.

# Criar um objeto linelist a partir dos dados limpos
linelist_data <- linelist::make_linelist(
  x = cleaned_data, # Dados de entrada
  id = "case_id", # Coluna para identificadores únicos de casos
  date_onset = "date_onset", # Coluna para a data de início dos sintomas
  gender = "gender" # Coluna para gênero
)

# Exibir o objeto linelist resultante

O pacote {linelist} fornece tags para variáveis epidemiológicas comuns e um conjunto de tipos de dados apropriados para cada uma. Você pode ver a lista de nomes de tags disponíveis e seus tipos de dados aceitáveis usando a função linelist::tags_types().

DicaDesafio

Vamos agora marcar variáveis adicionais. Em alguns conjuntos de dados, os nomes das variáveis podem não corresponder exatamente aos nomes predefinidos das tags. Nesses casos, você pode mapeá-las com base em como as variáveis foram definidas durante a coleta de dados. Você deve:

  • Explorar os nomes de tags disponíveis no {linelist}.
  • Encontrar quais outras variáveis no conjunto de dados de entrada podem ser associadas a qualquer uma dessas tags disponíveis.
  • Marcar essas variáveis como mostrado acima usando a função linelist::make_linelist().

Validação

Lembre-se do cenário acima, no qual uma alteração nos dados a montante (uma variável removida, renomeada ou reformatada) poderia quebrar sua análise silenciosamente. A validação é a verificação que detecta isso: executar linelist::validate_linelist() confirma que cada coluna marcada ainda está presente e ainda possui o tipo de dados esperado. Em uma análise contínua, você pode executá-la novamente a cada chegada de novos dados, de modo que qualquer alteração prejudicial seja sinalizada imediatamente, em vez de se propagar pelas etapas seguintes.

Para garantir que todas as variáveis marcadas estejam padronizadas e tenham os tipos de dados corretos, use a função linelist::validate_linelist(), como mostrado no exemplo abaixo:

linelist::validate_linelist(linelist_data)
'linelist_data' is a valid linelist object

Se o seu conjunto de dados exigir uma nova tag diferente daquelas definidas no pacote {linelist}, use allow_extra = TRUE ao criar o objeto linelist com seu tipo de dados correspondente usando a função linelist::make_linelist().

DicaDesafio

Mudanças nos tipos de variáveis durante a validação do linelist

Vamos supor o seguinte cenário durante um surto em andamento. Você percebe em determinado momento que o fluxo de dados em que você confiava recebeu um conjunto de novos registros (ou seja, linhas ou observações), e o tipo de dados de uma variável mudou.

Vamos considerar o exemplo em que o tipo da variável age mudou de double (<numeric>) para caractere (<character>).

Para simular essa situação:

  • Altere o tipo de dados da variável
  • Marque a variável em um linelist
  • Valide o linelist

Descreva como linelist::validate_linelist() reage quando há uma alteração no tipo de dados de uma variável dos dados de entrada.

# Alteração 2
# Execute este código linha por linha para identificar as alterações
cleaned_data %>%
  # simular uma alteração no tipo de dados
  dplyr::mutate(date_onset = as.character(date_onset)) %>%
  # marcar

# Execute este código linha por linha para identificar as alterações
cleaned_data %>%
  # simular uma alteração no tipo de dados
  dplyr::mutate(gender = as.factor(gender)) %>%
  dplyr::mutate(gender = as.integer(gender)) %>%
  # marcar
  linelist::make_linelist(gender = "gender") %>%
  # validar
  linelist::validate_linelist()

Recebemos mensagens de Error porque o tipo padrão dessas variáveis em linelist::tags_types() é diferente daquele que atribuímos.

A mensagem de Error nos informa que, para validar nosso linelist, devemos corrigir o tipo da variável de entrada para que corresponda ao tipo esperado pela tag. Em um script de análise de dados, podemos fazer isso adicionando uma etapa de limpeza ao pipeline.

Salvaguardas

Mecanismos de salvaguarda estão integrados implicitamente aos objetos linelist. Se você tentar remover qualquer uma das colunas marcadas, receberá uma mensagem de erro ou aviso, como mostrado no exemplo abaixo.

new_df <- linelist_data %>%
  dplyr::select(case_id, gender)
Warning: The following tags have lost their variable:
 date_onset:date_onset

A mensagem de Warning acima é a opção de saída padrão quando perdemos tags em um objeto linelist. No entanto, ela pode ser alterada para uma mensagem de Error usando a função linelist::lost_tags_action().

DicaDesafio

Explorar o comportamento de salvaguarda para tags perdidas

Vamos testar as implicações de mudar a configuração de salvaguarda de uma mensagem de Warning para uma de Error.

  • Primeiro, execute este código para contar a frequência de cada categoria dentro de uma variável categórica:
linelist_data %>%
  dplyr::select(case_id, gender) %>%
  dplyr::count(gender)
  • Defina o comportamento para tags perdidas em um linelist como “error”, da seguinte forma:
# definir o comportamento como "error"
linelist::lost_tags_action(action = "error")
  • Agora, execute novamente o bloco de código acima com dplyr::count().

Identifique:

  • Qual é a diferença na saída entre um Warning e um Error?

  • Quais poderiam ser as implicações dessa alteração para o seu pipeline diário de análise de dados durante a resposta a um surto?

NotaSolução

Decidir entre uma mensagem de Warning ou de Error dependerá do nível de atenção ou flexibilidade de que você precisa ao perder tags. Um Warning alertará você sobre uma alteração, mas continuará executando o código nas etapas seguintes. Um Error interromperá seu pipeline de análise e o restante não será executado.

Um script de leitura, limpeza e validação de dados pode exigir um pipeline mais estável ou rígido. Uma análise exploratória de dados pode exigir uma abordagem mais flexível. Esses dois processos podem ser isolados em scripts ou repositórios diferentes para ajustar as salvaguardas de acordo com as suas necessidades.

Antes de continuar, retorne a configuração para a opção padrão de Warning:

# redefinir o comportamento para a opção padrão: "warning"
linelist::lost_tags_action()
Lost tags will now issue a warning.

NotaChecklist

Quando devo usar o {linelist}?

A análise de dados durante a resposta a um surto ou na vigilância de eventos de massa exige um conjunto diferente de salvaguardas de dados se comparada a situações habituais de pesquisa. Por exemplo, seus dados sofrerão alterações ou serão atualizados ao longo do tempo (ex.: novos registros, novas variáveis, variáveis renomeadas).

O {linelist} é mais adequado para esse tipo de análise contínua ou de longa duração. Consulte a seção da vinheta “Get started” sobre Quando devo considerar o uso do {linelist}? para mais informações.
